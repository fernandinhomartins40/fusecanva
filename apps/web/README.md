# Fuse Studio — implementação inicial

Este diretório contém a aplicação guiada por [`../../IMPLEMENTATION-PLAN.md`](../../IMPLEMENTATION-PLAN.md). O corpus em `../../analysis/` permanece intacto como referência da auditoria.

## Executar localmente

Abra dois terminais nesta pasta. No primeiro, inicie a API:

```powershell
npm.cmd install
npm.cmd run server
```

No segundo, inicie a aplicação web:

```powershell
npm.cmd run dev
```

O Vite encaminha `/api` para `http://127.0.0.1:8787`. A API cria o banco em `.data/studio.sqlite`; use `STUDIO_DB_PATH` para apontar a outro arquivo. Uploads persistentes ficam como objetos locais enderecados por SHA-256 em `.data/media`; configure `STUDIO_MEDIA_OBJECT_DIR` para outro diretorio. O SQLite guarda metadados e referencias, e a API reidrata a imagem no mesmo contrato de dados. As imagens antigas embutidas sao migradas na inicializacao. Para uma implantacao distribuida, configure um volume compartilhado ou substitua o adapter local por armazenamento de objetos. Configure `APP_ORIGINS` com origens permitidas separadas por virgulas.

Para habilitar o rascunho de texto por IA, copie `.env.example` para `.env`. `STUDIO_AI_MODE=sandbox` ativa respostas determinísticas sem rede; `STUDIO_AI_MODE=openai-compatible` usa `STUDIO_AI_BASE_URL`, `STUDIO_AI_API_KEY` e `STUDIO_AI_MODEL` para um endpoint compatível com Chat Completions. Sem configuração, a função permanece desativada. O segredo fica no servidor, e a rota só permite geração a quem edita o documento na nuvem.

## Verificações

```powershell
npm.cmd test
npm.cmd run lint
npm.cmd run build
npm.cmd run test:browser:collaboration-reconnect
npm.cmd run test:browser:doc-inline
npm.cmd run test:browser:sheet
```

Os testes cobrem migracao do IndexedDB v1/v2 para v3, preservacao/reidratacao de assets locais, referencias compartilhadas entre documentos e coleta apos a ultima referencia, persistencia colaborativa de imagem/notas/conectores/grupos, remapeamento de conectores e grupos ao duplicar quadros, movimento conjunto e limpeza de relacoes na exclusao, acompanhamento de apresentações ao vivo via SSE, exclusao das notas de apresentador da renderizacao dos slides, persistencia Docs, operacoes de pagina e tabela, API isolada com ACL/SSE, merge concorrente e estrutura de PDFs multipagina exportados. O ensaio separado `npm.cmd run test:browser:collaboration-reconnect` força uma falha de salvamento por rede offline e reproduz os callbacks `error`/`open` do EventSource para verificar a recuperação do autosave; não verifica a reconexão automática do transporte do navegador. O mesmo ensaio cria um conector pela lista de camadas e confirma que a operação colaborativa o persiste com os dois endpoints sem snapshot PUT redundante.

O ensaio `npm.cmd run test:browser:doc-inline` valida edição/seleção/cursor e marcas inline, depois verifica paginação Docs em desktop de 1280 px e mobile de 390 px sem overflow horizontal. Compara a contagem de folhas do editor e do renderizador PDF e confirma que blocos longos ganham uma página ampliada em vez de serem cortados. A paginação mobile reflowa em mais folhas do que o PDF A4 desktop; tabelas extensas e equivalência visual por pixels ainda precisam de casos próprios.

No ensaio `npm.cmd run test:browser:collaboration-reconnect`, o proprietário também altera na interface o papel de uma conta de editor para comentarista e o teste confirma a ACL atualizada no servidor. A conta afetada recebe `access.changed` quando conectada. Convites pendentes para projetos/equipes oferecem link de aceitação; recuperação de senha envia link de uso único e revoga sessões anteriores. O envio por e-mail é opcional e usa Resend quando `STUDIO_EMAIL_PROVIDER=resend`, `STUDIO_EMAIL_API_KEY`, `STUDIO_EMAIL_FROM` e `STUDIO_PUBLIC_APP_URL` estão configurados no servidor. Sem configuração, nenhum e-mail externo é enviado; os testes injetam adaptador falso.

## Estado funcional

- A biblioteca aceita CSV e workbooks `.xlsx`, criando planilhas editáveis locais ou na nuvem. CSV detecta vírgula, ponto e vírgula ou tabulação; preserva acentos, aspas escapadas e campos com quebras de linha, com limite de 5 MB, 10 mil linhas, 256 colunas e 500 mil células. XLSX preserva abas, valores, fórmulas, mesclagens horizontais e formatos básicos de número/data; limita o arquivo a 5 MB, 100 abas, 1.000 linhas por aba, 200 colunas e 500 mil células. A exportação XLSX inclui todas as abas; CSV continua limitado à aba atual. XLS binário, mesclagens verticais e estilos/objetos avançados não são suportados.
- A grade aceita colagem retangular de células via clipboard (tabulações e quebras de linha), como uma única alteração passível de Undo/Redo, respeitando o limite de 1.000 linhas por 200 colunas e mantendo intacto o conteúdo externo ao intervalo. O ensaio Chrome cobre a interação; células mescladas e tradução de referências de fórmulas ao copiar ainda exigem regras específicas.
- Em planilhas na nuvem, edição, colagem, preenchimento para baixo, formatos numéricos, mesclagem/desmesclagem e inclusão de linhas/colunas usam operações atômicas idempotentes. Inclusões estruturais são anexadas à grade atual e combinam mesmo quando enviadas com revisão antiga; células ou formatos independentes também combinam, enquanto sobreposições retornam conflito. Alterações remotas chegam por SSE e os comandos operacionais não disparam snapshots redundantes. Os demais editores ainda usam snapshots/merge de três vias; não há CRDT global.
- Texto de blocos e células de tabelas em Docs usam `doc.block.text.set` e `doc.table.cell.set`, com revisão-base e ID idempotente. Edições de texto em trechos independentes são rebaseadas no mesmo bloco, preservando marcas inline; sobreposições e disputas na mesma célula retornam conflito. Alterações remotas chegam por SSE e não geram snapshots redundantes. Estrutura, estilo e outras operações Docs ainda usam snapshots/merge de três vias.
- Alterações de propriedades de elementos do canvas (posição, tamanho, texto e estilo) usam `design.element.patch`; mudanças em propriedades diferentes do mesmo elemento combinam com revisão antiga, e concorrência na mesma propriedade retorna conflito. Criação/exclusão, grupos, ordem de camadas e estrutura de páginas/slides usam operações atômicas; duplicação de páginas verifica se a origem mudou, exclusão verifica se a página foi editada, e a última página não pode ser removida. `design.page.patch` sincroniza nome e cor de fundo por campo. O ensaio Chrome cobre reordenação de camadas, inserção/exclusão remotas de página e edição de nome/fundo via SSE, sem snapshots redundantes. Estruturas restantes de Docs e histórico colaborativo global ainda usam snapshots/merge de três vias.
- Comentários em documentos na nuvem agora podem ter respostas em threads de um nível e ser resolvidos/reabertos. Respostas herdam o vínculo à página/elemento, só podem apontar para comentários principais do mesmo documento; a resolução registra usuário e horário. Ambas as mudanças são publicadas no SSE compartilhado, e a migração SQLite adiciona os campos sem apagar comentários existentes.
- O assistente de texto gera rascunhos por adapter Chat Completions configurável, com timeout e limite de saída. Sandbox é explícito e marcado na interface como demonstração; o modo real nunca é chamado pelos testes. O rascunho só entra no design ou Docs após ação do usuário. Imagens por IA, histórico de prompts e controles de privacidade por provedor ainda não estão implementados.

- Edits concorrentes na mesma sequência de texto são combinadas por trechos Unicode quando não se sobrepõem; a mesma região modificada e inserções no mesmo ponto geram conflito para revisão. Marcas inline de negrito/itálico também são deslocadas e combinadas por intervalo no Docs. O limite de custo usa um trecho conservador para strings muito longas. Isso atende blocos do Docs, texto de designs e valores textuais simples de células; sincronização por operações nos demais editores/CRDT ainda não existe.
- Se outra aba atualizar o schema do IndexedDB, a conexão fechada é removida do cache e reaberta na próxima leitura/gravação. O teste de persistência simula `versionchange` e confirma a leitura dos documentos após a reabertura.
- A biblioteca de projetos e a biblioteca de imagens ficam no IndexedDB do navegador.
- O editor de designs oferece paginas A4 que podem ser duplicadas, reordenadas e excluidas (mantendo ao menos uma), texto, formas e imagens, camadas, atalhos, Undo/Redo, PNG/JPG da pagina atual e PDF com todas as paginas. O módulo Docs inclui blocos de texto com formatação inline em negrito/itálico (por botões e Ctrl/Cmd+B/I), tabelas editáveis 4 × 3, edição de células, inclusão/remoção de linhas e colunas, navegação por Tab, criação de linha no fim da tabela, localizar/substituir literal em todas as páginas e células (com opção de diferenciar maiúsculas/minúsculas), estilos básicos, autosave e exportação PDF/PNG/JPG.
- A galeria Modelos oferece três composições vetoriais editáveis. Cada uso gera identificadores novos e cria um documento independente no armazenamento local ou na nuvem; ainda não há marketplace nem catálogo remoto.
- O primeiro fluxo de quadro branco pode ser criado localmente ou na nuvem. Ele oferece área de trabalho ampla (3200 × 2000), pan com mouse/toque, zoom ancorado ao ponteiro e enquadramento, seleção por caixa ao arrastar no fundo do quadro, texto/formas/imagens/notas adesivas, conectores com pontos de borda escolhidos no canvas que acompanham movimento/redimensionamento/rotação, desenho vetorial livre por mouse/caneta/toque, seleção múltipla por Shift ou modo móvel e grupos planos que movem, duplicam e excluem seus membros sem achatar os objetos. Seleções múltiplas têm alinhamento às bordas/centros e distribuição horizontal/vertical pela caixa visual (incluindo rotação), disponíveis no painel e na barra móvel como ações únicas de histórico. Âncoras, elementos, grupos e conectores participam do histórico, autosave, colaboração, previews e exportação; a criação de conector envia uma operação atômica com referências aos dois elementos e é validada no servidor apenas para documentos whiteboard. As âncoras são um comportamento implementado aqui; a auditoria REA disponível identifica campos candidatos do schema, sem comprovar a interação equivalente no Canva. Ainda faltam grupos aninhados, snapping por proximidade/guias e outras ferramentas avançadas próprias de quadro.
- Apresentações podem ser criadas localmente ou na nuvem em formato widescreen 16:9. Elas reutilizam o editor de páginas, salvamento compartilhado e exportação existente; a lista de slides tem miniaturas, seleção direta, renomeação e criação. Nome e fundo do slide usam operações colaborativas por campo; os controles duplicam, reordenam e excluem slides por operações de página. Notas editáveis por slide são salvas por `design.page.notes.set`: mudanças em trechos independentes combinam com revisão antiga, sobreposições geram conflito, e as notas ficam fora da exibição e exportação dos slides. API e Chrome validam o fluxo e a atualização SSE sem snapshot redundante. No modo de apresentador, as notas do slide atual e a prévia do próximo acompanham a mesma navegação do slide principal; o modo de tela limpa oculta esse painel. Em projetos na nuvem, colaboradores autorizados podem acompanhar a apresentação ao vivo, inclusive ao entrar depois; só há um apresentador ativo por projeto, apenas ele controla os slides, e encerrar a sessão ou fechar todas as conexões dele limpa o estado ativo. A apresentação em tela cheia suporta teclado (setas, Page Up/Down, Home, End e Espaço), controles visíveis, gesto de deslizar e saída por Esc. Transições e temporização ainda não estão implementadas.
- O primeiro fluxo de planilha é editável localmente e na nuvem. A grade inicial tem 30 linhas por 12 colunas, pode crescer por linhas/colunas, aceita conteúdo e fórmulas com referências A1, operações aritméticas e SOMA/SUM, MÉDIA/AVERAGE, MÍNIMO/MIN, MÁXIMO/MAX e CONT.NÚM/COUNT em intervalos; dependências são recalculadas e ciclos/divisão por zero/expressões inválidas são sinalizados. Enter/Tab navegam a grade, Shift+clique e Shift+setas selecionam uma faixa horizontal; células vazias podem ser mescladas/desfeitas sem sobrescrever conteúdo, e referências a coordenadas cobertas mantêm a referência e avaliam como zero. A barra de fórmula edita a célula ativa; formatos padrão, moeda e porcentagem são aplicados à seleção e persistem sem alterar o valor bruto. Preencher para baixo copia fórmulas ajustando referências relativas e preservando absolutas. Dados, formatos e mesclagens são salvos no modelo comum, autosave e colaboração. Ensaios em Chrome validam fórmulas localizadas, recálculo, formatos, preenchimento, mesclagem persistida, Undo/Redo, rolagem móvel a 390 px e ausência de overflow. Ainda faltam referências entre planilhas, funções avançadas, gráficos, colar/copiar faixas em duas dimensões e equivalência visual/funcional contra os casos auditados.
- Uploads validam a decodificacao e limitam arquivos a 10 MB e 32 megapixels. A biblioteca local reutiliza arquivos byte a byte identicos por SHA-256 e so adiciona a imagem ao design depois de persistir a midia. No servidor, arquivos persistentes ficam fora do SQLite em objetos com chave SHA-256; bibliotecas de equipe e documento guardam metadados e referencias e as respostas reidratam o mesmo data URI. A migracao desloca automaticamente uploads legados do banco para o diretorio de objetos. Documentos antigos com imagens embutidas sao preservados e passam a usar referencias no proximo salvamento. O transporte JSON ainda usa base64 e continua limitado a 16 MB por requisicao.
- O editor de imagem oferece cinco presets raster próprios (Suave, Vintage, Mono, Toque de cor e Duotone). O preset selecionado fica no elemento, participa do histórico/autosave, da validação de operações colaborativas e da exportação PNG/PDF; o pipeline preserva alpha e recorte. A Borracha oferece máscara manual não destrutiva, modos Apagar/Restaurar, tamanho de pincel, desfazer o último traço e limpar a máscara; ela persiste no design e aparece na exportação. Esses algoritmos são aproximações próprias, sem equivalência de pixels aprovada contra o Canva. Remoção automática de fundo, estilos artísticos e outros processadores ainda dependem de implementação ou de um adapter configurado.
- A interface conecta cadastro/login à API e oferece biblioteca em nuvem, criação/abertura/duplicação, autosave remoto, compartilhamento com contas existentes, comentários e modos de leitura/edição por papel. Um teste de API confirma que imagens embutidas em designs remotos permanecem disponíveis ao editor autorizado após abrir, editar, salvar e reabrir o projeto; os bytes da biblioteca local do proprietário não são necessários no dispositivo colaborador.
- Eventos SSE autenticados atualizam projetos, comentários, papéis e presença por documento (usuários conectados, contagem de abas e ponteiros remotos no editor de designs, transmitidos por SSE com coordenadas normalizadas). O editor mostra conexão/reconexão e seleções de objetos remotas; no callback `onopen`, consulta a revisão atual e reaciona o autosave para rascunhos locais pendentes mesmo que a revisão remota não tenha mudado. A fila de gravação lê a revisão-base no momento da execução. O ensaio de navegador simula a falha de salvamento sem rede e reproduz os callbacks `error`/`open`; a reconexão automática do EventSource ainda precisa de teste separado. O servidor guarda até 100 snapshots-base e combina automaticamente gravações atrasadas com mudanças independentes, inclusive por coordenada de célula em tabelas Docs e planilhas. Edições na mesma célula conflitam explicitamente; intervalos mesclados independentes combinam se não se sobrepõem. Coedição por operações/CRDT nos demais editores ainda não existe; seleções de blocos e células Docs são transmitidas em tempo real.
- Em conflito de revisão, o editor oferece recarregar a versão remota ou guardar uma cópia local.
- Projetos locais não são migrados automaticamente para a nuvem. Ainda faltam coedição simultânea CRDT, recuperação/verificação de conta, IA de imagem, Apps, publicação de Sites, impressão e controles avançados de privacidade para provedores. O e-mail de convites depende de configuração explícita do Resend; sem isso, a colaboração continua disponível por links.
- O Docs inicial reutiliza persistência e compartilhamento; a paginação visual distribui blocos automaticamente em folhas dentro de cada página manual e preserva texto e posição do cursor. Localizar/substituir abrange texto dos blocos e células de tabelas em todas as páginas, permite correspondência literal e sensível a maiúsculas/minúsculas, mostra a contagem e substitui tudo numa única alteração persistida. A formatação inline por marcas de intervalo é editável em trechos, preservada na edição/colaboração e exportada em PDF e imagem, incluindo tabelas no fluxo geral. Ainda faltam estilos avançados de borda, cabeçalhos/rodapés, validação visual automatizada e equivalência dos atalhos observados; consulte o [plano](../../IMPLEMENTATION-PLAN.md) e a [matriz dos 131 casos](../../IMPLEMENTATION-TRACEABILITY.md).

O backend usa o módulo SQLite embutido no Node para desenvolvimento local. Veja no plano a pendência de selecionar armazenamento de produção antes de abrir o serviço externamente.





- The image inspector and image-edit panel share brightness, contrast, and saturation sliders plus numeric fields. Contrast/saturation are part of the image model, collaboration validation, local persistence, preview filters, and PNG/PDF raster export; values are clamped to -100..100. These transforms are implemented locally and have not been matched pixel-for-pixel to Canva.

- Starter templates include searchable tags and metadata for document type, layout format, palette, and original Fuse Studio provenance. The gallery filters by type, color family, license class, category, and language; filter state is preserved in the route. The current ten templates are original starter assets, not a third-party asset marketplace.

## Optional external providers

Image generation defaults to the local sandbox. To use a server-side OpenAI Images API compatible endpoint, set `STUDIO_IMAGE_AI_MODE=openai-compatible`, `STUDIO_IMAGE_AI_BASE_URL`, `STUDIO_IMAGE_AI_API_KEY`, and `STUDIO_IMAGE_AI_MODEL` in `.env`. The API key stays on the server; tests use injected adapters and do not call external providers. Invitation email is separately opt-in with `STUDIO_EMAIL_PROVIDER=resend`, `STUDIO_EMAIL_API_KEY`, `STUDIO_EMAIL_FROM`, and `STUDIO_PUBLIC_APP_URL`; without them invitations remain link-only. Connected Apps examples do not imply OAuth or provider integration is configured.
